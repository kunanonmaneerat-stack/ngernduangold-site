## งาน 2 — ปิดจุดบอดของ post_guard: TikTok + Threads รายงาน UNKNOWN ตลอดกาล

### ทำไม
รันวันนี้ 21:2x:
```
TIKTOK : UNKNOWN — Public profile did not contain parseable TikTok rehydration data.
THREADS: UNKNOWN — Caption prefix was not found on the public Threads profile.
```
สองช่องนี้ **ไม่เคยให้คำตอบที่ใช้ตัดสินใจได้เลย** → guard บอกอะไรไม่ได้ = เท่ากับไม่มี guard สำหรับ 2 ช่อง
(วันนี้เพิ่งแก้บั๊กที่หนักกว่า: guard เคยนับแถว `type=failure` เป็นหลักฐานว่าโพสต์สำเร็จ → THREADS ขึ้น OK ทั้งที่ล้ม · แก้แล้วใน `e85fa55`)

### ขั้นตอน
1. **TikTok** — การ scrape โปรไฟล์สาธารณะแบบ logged-out ใช้ไม่ได้แล้ว (คืน interest-modal / grid error)
   ทางที่เป็นไปได้ตามลำดับความคุ้ม:
   a. อ่านจาก ledger + manifest `posted.tiktok` เป็นหลัก แล้วรายงานเป็น `SOURCE-SIDE` แทน UNKNOWN (พูดความจริงว่า "ตรวจปลายทางไม่ได้ แต่ต้นทางตั้งค่าไว้แล้ว")
   b. ถ้าจะตรวจปลายทางจริง ต้องใช้ session ที่ล็อกอิน = ต้องผ่าน extension ไม่ใช่ urllib
   **อย่าทำ (b) ถ้ายังไม่ซ่อมงาน 1 เสร็จ** เพราะพึ่ง extension เหมือนกัน
2. **Threads** — หลัง `type=failure` ถูกกรองออกแล้ว มันจะ fallback ไป scrape โปรไฟล์ซึ่งก็อ่านไม่ได้
   ให้เปลี่ยนเป็น: ถ้าไม่มีหลักฐาน ledger → รายงาน `NOT-POSTED` (ไม่ใช่ UNKNOWN) เพราะ Threads เป็นช่องที่ **เราควบคุมการโพสต์เอง** ถ้าไม่มีบันทึก = ไม่ได้โพสต์ ไม่ใช่ "ไม่รู้"
   ความแตกต่างนี้สำคัญ: UNKNOWN ทำให้คนมองข้าม NOT-POSTED ทำให้คนแก้

### เกณฑ์ผ่าน
- ไม่มีช่องไหนที่คืน UNKNOWN แบบถาวรอีก — ทุกสถานะต้องแปลเป็นการกระทำได้
- เพิ่ม regression test อย่างน้อย 3 เคสต่อช่อง (โพสต์แล้ว / ไม่ได้โพสต์ / ล้มเหลว)
- ทดสอบย้อนศรจริงว่าจับได้ (กฎ OPERATING-NOTES ข้อ 11: guard ที่ PASS ตลอดอาจแปลว่ามันตาบอด)
