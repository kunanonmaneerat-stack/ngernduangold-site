## 3. เปิดกลับยังไง — เรียงลำดับ

**ขั้นที่ 0 — ก่อนเปิดอะไรเลย**
```
cd C:\Users\nL_ku\ngernduangold-site
py tools\preflight.py
py tools\runway_guard.py
py tools\encoding_probe.py
```
ดูว่ามีอะไรพังระหว่างที่หยุดไปไหม (cron layer เดินตลอด รายงานจะสดอยู่แล้ว)

**ขั้นที่ 1 — แก้ blackout ใน `policy.json`**
ใส่ `until` เป็นวันที่เปิดกลับจริง · **ห้ามลบ entry ทิ้ง** มันคือคำอธิบายของความเงียบช่วงนั้น
ถ้าไม่ใส่ `until` รอบตรวจถัดไปจะคิดว่ายังพักอยู่ตลอดกาล

**ขั้นที่ 2 — เคลียร์ตัวบล็อก**
ตอบให้ได้ก่อนว่า **ไฟล์ PDF ชุดจดหมายมีหรือยัง**
- มี → CC ต่อท่อ Gumroad ~20 นาที แล้วอัปเดต `products.letter-kit-199.deliverable`
- ไม่มี → **เอา CTA 199฿ ลงก่อน** อย่าเปิดสายโพสต์ทั้งที่หน้าเว็บรับเงินแล้วส่งของไม่ได้

**ขั้นที่ 3 — เปิดงานทีละชั้น อย่าเปิดหมดวันเดียว**
1. `cowork-task-watchdog` + `ngernduangold-uptime-monitor` (ตาก่อน)
2. `ngernduangold-post-guard-daily` + `ngernduangold-channel-heartbeat` (ตัววัด)
3. โพสต์: `knowledge-post-noon` → `fb-page-comment-link` → `yt-comment-link`
4. วิดีโอ: `threads-daily` + `threads-video-idle-window` (ต่อเมื่อคิวมีของแล้ว)
> เปิดทีละชั้นเพื่อให้รู้ว่าถ้ามีอะไรพัง มันพังเพราะตัวไหน · เปิดพร้อมกันหมดแล้วเจอปัญหา = แยกไม่ออก

**ขั้นที่ 4 — เติมของก่อนเปิดสายโพสต์**
- คลังข้อความ: เขียนชุดถัดจาก 15 ส.ค. (มี task พร้อม แค่เปิดแล้วตั้งวันใหม่)
- คิววิดีโอ: เคาะ gate batch3 ก่อน แล้วค่อยลบ/ยืด `planned_park` ตามผล
> **ห้ามเปิดงานโพสต์ทั้งที่คลังว่าง** — จะได้ failure row กองหนึ่งที่ไม่ได้บอกอะไรนอกจากว่าเราลืมเติมของ

**ขั้นที่ 5 — ตั้งวันใหม่ให้ task ที่ยิงครั้งเดียวและพลาดไปแล้ว**
`ngernduangold-batch3-gate-final` · `ngernduangold-knowledge-library-refill` · `ngernduangold-fb-reel-backfill`
ทั้งสามตัวมี `fireAt`/หน้าต่างที่ผ่านไปแล้ว **ต้องตั้งวันใหม่ ไม่ใช่แค่เปิด**
