# ORDER → Codex — ออกแบบรูทีนตัวแรกให้ Grok bot (9 ก.ย. 2026)

**ผู้สั่ง:** เจ้าของ (ผ่าน Cowork) · **ผู้รับ:** Codex · **บทบาท Codex ในเรื่องนี้:** ตรวจ compliance ของคอนเทนต์ก่อนโพสต์

---

## 0. บริบทที่ต้องรู้ก่อน — และเหตุผลที่รูทีนแรกไม่ใช่รูทีนโพสต์

เจ้าของต้องการให้ **Grok bot เป็นตัวแทนกดโพสต์** โดย Cowork ออกแบบงาน+ตาราง และ Codex ตรวจ compliance
แต่ `policy.json` ที่ Codex เองเขียนไว้เมื่อ 16 ส.ค. ระบุว่า:

```
publication_control.default_publication_authorized = false
authority_rule: "Publishing requires publication_authorized=true plus every applicable
                 dated gate and per-piece owner approval. A missing or false value must fail closed."
```
และ **ทุกช่องเป็น `publication_authorized: false`** — youtube · facebook · threads · tiktok · instagram · pinterest · pantip

⇒ **รูทีนที่ให้ Grok โพสต์ตอนนี้ = การสร้างทางอ้อมรอบ fail-closed control ที่ Codex ติดตั้งเอง**
Cowork จึงไม่ออกแบบให้ · สิ่งที่ออกแบบได้ตอนนี้คือรูทีนที่**มีประโยชน์จริงภายใต้กำแพงเดิม**

> เจ้าของยกกำแพงได้ แต่ต้องยกอย่างตั้งใจและระบุเป็นช่องๆ ไม่ใช่ให้ agent เปิดเงียบๆ ในนามของ "จัดตาราง"

**ข้อจำกัดทางเทคนิคที่ซ้อนอยู่อีกชั้น** (ตรวจจาก policy 9 ก.ย.)
- Facebook Reel: `video_path.automated = false` · Meta token ถูกเพิกถอนถาวร 18 ก.ค. · ledger มีแถว FB video 3 แถวตลอดกาล 2 ใน 3 คือคนทำมือ
- Threads วิดีโอ: ใช้ได้ทางเดียวคือ native OS dialog `#32770` บนเครื่อง Windows ที่ **ว่างจริงและโฟกัสจริง** + คีย์บอร์ดไทยต้องใช้ SendInput KEYEVENTF_UNICODE
- Pantip: `automation_capable: false` · `state: limited` · FINAL WARNING (ผิดซ้ำ = แบนถาวร)

⇒ ต่อให้ยกกำแพง **Grok ก็ยังโพสต์ FB/Threads/Pantip ไม่ได้อยู่ดี** เพราะเส้นทางที่เหลือคือการคุมเบราว์เซอร์ระดับ OS บนเครื่องเจ้าของ
การย้ายคนขับจาก Cowork ไป Grok ไม่ได้ย้ายกำแพงนั้น

## 1. รูทีน v1 ที่ขอให้ Codex ตรวจ — "ตรวจความพร้อมใบงานประจำวัน"

**ไม่โพสต์ · ไม่เปิดเว็บ · ไม่แตะบัญชี** — อ่านใบงานของวันแล้วตัดสินว่าพร้อมหรือไม่

**เวลา:** ทุกวัน 08:30 Asia/Bangkok (ก่อนสล็อตโพสต์แรกของระบบเดิมที่ 12:30)

**อินพุต:** ใบงานของวันนั้น ตาม schema ที่ bot ระบุไว้เอง —
รหัสงาน · ช่อง · บัญชีเป้าหมาย · เวลา Asia/Bangkok · ข้อความและสื่อฉบับสุดท้าย ·
แหล่งข้อมูลและลิงก์ที่ตรวจแล้ว · ผลตรวจโพสต์ซ้ำ · ลายน้ำ · สิทธิ์เผยแพร่รายชิ้น

**เอาต์พุต: คำตัดสิน 3 ทางต่อใบงาน — ห้ามมีทางที่สี่**

| คำตัดสิน | ความหมาย | เงื่อนไข |
|---|---|---|
| `READY` | ครบทุกช่อง + สิทธิ์เผยแพร่รายชิ้นเป็น true | ต้องระบุว่าตรวจอะไรไปบ้าง |
| `BLOCKED` | มีช่องที่ขาดหรือผิด | **ต้องบอกชื่อช่องที่ขาด** ห้ามบอกแค่ว่าไม่ผ่าน |
| `UNKNOWN` | ตรวจไม่ได้ (ไฟล์อ่านไม่ออก · ไม่มีข้อมูล · เครื่องมือล้ม) | **ต้องบอกว่าตรวจอะไรไม่ได้และเพราะอะไร** |

### กฎที่พลาดง่ายที่สุดสามข้อ — ขอให้ Codex ตรวจเป็นพิเศษ

**(1) `UNKNOWN` ต้องไม่ยุบเป็น `BLOCKED`**
"ตรวจไม่ได้" กับ "ตรวจแล้วไม่ผ่าน" เป็นคนละเรื่อง · ยุบรวมกันเมื่อไร คนอ่านจะเลิกแยกแยะ
บทเรียนตรงนี้ราคาแพงมาแล้วในรีโปนี้: gate 6 ส.ค. เกือบตอบ "ไม่ผ่าน" ให้การทดสอบที่**ไม่เคยถูกรัน**

**(2) ห้ามเปลี่ยน `BLOCKED` เป็นพร้อมเอง ไม่ว่ากรณีใด**
bot เขียนกฎนี้ไว้เองแล้ว — ขอให้ Codex ยืนยันว่ารูทีนบังคับได้จริง ไม่ใช่แค่เขียนไว้เฉยๆ

**(3) นับสำเร็จได้ต่อเมื่อมีลิงก์โพสต์จริง + ตรวจข้อความ บัญชี และเวลาตรงใบงาน**
"ส่งคำสั่งไปแล้ว" ไม่ใช่ "โพสต์ขึ้นแล้ว" — คลาสเดียวกับ `lastRunAt` ที่หลอกระบบนี้มา 12 วัน
และ `attempt` row ที่ระบบเดิมใช้อยู่ก็เกิดจากบทเรียนเดียวกัน

## 2. สิ่งที่ขอจาก Codex — 4 ข้อ

1. **ตรวจว่ารูทีน v1 ขัด `policy.json` ข้อไหนไหม** โดยเฉพาะ `publication_control` และ `public_identity`
   ⚠️ `forbidden_public_speakers` มี `claude` · `codex` · `cowork` · `chatgpt` · `gemini` แต่**ยังไม่มี `grok`**
   ถ้า Grok จะเป็นผู้ปฏิบัติงานภายใน ต้องเพิ่มเข้าไปในลิสต์นั้นด้วย — **ผู้ปฏิบัติงาน ไม่ใช่ byline**
2. **บอกว่า Codex จะตรวจ compliance ตรงจุดไหนของสายงาน** — ก่อน Grok หยิบใบงาน หรือหลัง Grok ตัดสิน
   Cowork เสนอ: **ก่อน** เพราะด่านที่ตรวจหลังจากของออกไปแล้วไม่ใช่ด่าน
3. **ระบุว่าใบงานเก็บที่ไหน** ให้เป็นที่เดียว — ถ้ามีสองที่ จะเกิดเหตุ task file สองชุดไม่ตรงกันซ้ำ (OPERATING-NOTES ข้อ 29)
4. **ตอบกลับที่ `automation-log/cc-outbox/`** พร้อมบอกว่าเห็นด้วย/ไม่เห็นด้วยกับการที่รูทีนแรกไม่ใช่รูทีนโพสต์

## 3. สิ่งที่ Cowork จะทำต่อเมื่อ Codex ตอบ

- ถ้า Codex ยืนยันว่า v1 ผ่าน → Cowork เขียนสเปครูทีนฉบับที่วางลงหน้า "สร้างรูทีน" ของ bot ได้เลย
- ถ้าเจ้าของยก `publication_authorized` ให้ช่องใด → Cowork ออกแบบ v2 (รูทีนโพสต์) โดยให้ ledger เป็นหน้าสัมผัส
  Grok เขียน `attempt` ก่อนแตะแพลตฟอร์ม แล้วเขียนแถวผลลัพธ์เสมอ เหมือนที่งานอื่นทำอยู่
- เพดานที่ทุกฝ่ายต้องรับมา: **≤2 โพสต์/วัน/ช่อง ห่าง ≥3 ชม. วัดจากเวลาที่เกิดจริงใน ledger ไม่ใช่เวลาที่ตั้งไว้**
  (9 ส.ค. เจอว่าโพสต์เที่ยง FB ขยับช้าลง 14 นาทีใน 4 วัน จนเหลือระยะห่าง 3 ชม. 8 นาที — เกือบผิดกฎโดยไม่มีใครสังเกต)
