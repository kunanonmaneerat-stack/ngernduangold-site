### 🟡 P1 — 1–2 สัปดาห์

**P1-1 · ทะเบียนงานกลาง `.system_control/tasks.json`** *(R3)*
ฟิลด์: `id · owner(cowork|cc) · cadence · governing_quota · enabled · last_seen`
ทุกตัวตรวจอ่านทะเบียนนี้แทนการเรียก `list_scheduled_tasks` (ซึ่งเห็นแค่ครึ่งเดียว)
พร้อม check ใหม่: **จำนวนโฟลเดอร์บนดิสก์ ต้องเท่ากับจำนวนแถวในทะเบียน** — ส่วนต่างคือที่ที่ปัญหาไปนอน

**P1-2 · check ใหม่: `cadence ≤ quota`** *(R4)*
อ่าน `governing_quota` จากทะเบียน เทียบกับ cadence จริง → รันถี่กว่าโควตาที่ทำได้ = WARN
กันไม่ให้ "รายวันทั้งที่โควตา 3/สัปดาห์" กลับมาอีก **โดยไม่ต้องมีใครสังเกตเอง**

**P1-3 · `tools/scan_text.py` — ตัวช่วยค้นคีย์เวิร์ดตัวเดียวของระบบ** *(R2)*
บังคับ 3 กฎที่พลาดซ้ำ 4 ครั้งแล้ว:
1. คำสั้น (`ig` `fb` `yt`) แมตช์**ทั้งคำ**เท่านั้น
2. วันที่ใน**ชื่อไฟล์** = การอ้างอิง ไม่ใช่การประกาศ → ตัดก่อนสแกน
3. คำที่อยู่ใน**ประโยคปฏิเสธ** ("ห้ามใช้ X") ไม่ใช่การใช้ X
แล้วให้ `preflight` · `agent-auditor` · gate ทุกตัวเรียกใช้ตัวนี้ — เลิกเขียน grep เอง

**P1-4 · เลือกทางเรื่อง `log_run`** *(R3)*
บังคับทุกงานเรียก **หรือ** เลิกใช้เป็นตัวชี้สุขภาพ — **ห้ามอยู่กึ่งกลาง** เพราะครอบคลุมบางส่วนทำให้แยกไม่ออกระหว่าง "งานตาย" กับ "งานไม่เขียน log" แล้วสุดท้ายจะเลิกเชื่อทั้งอัน

## ส่วนที่ 4 — กฎที่ได้จากรอบนี้ (เข้า OPERATING-NOTES ข้อ 26–28)

1. **จำนวนงานที่ระบบ "รู้ว่ามี" ต้องเท่ากับที่ "มีจริงบนดิสก์"** — ส่วนต่างคือจุดบอด
2. **ผลลัพธ์ที่ถูกมาตลอด ไม่ใช่หลักฐานว่าคำสั่งถูก** — `pantip-monitor` ขึ้น `posted:0` ทุกรอบ ทั้งที่ไฟล์สั่งให้โพสต์ได้เลย · สิ่งที่กันอยู่คือดุลยพินิจ ไม่ใช่กฎ
3. **FAIL เท็จ อันตรายกว่า guard เงียบ** — FAIL คือด่านแข็ง เท็จเมื่อไรคือบล็อกงานจริง หรือสอนให้คนเลื่อนผ่าน
4. **เรียงด่านตาม ต้นทุน × ความถี่ที่เส้นทางนั้นเกิด** ไม่ใช่ตามลำดับที่ดูเป็นเหตุเป็นผล
5. **cadence ควรเท่าโควตาที่ควบคุมมัน** — แล้วตารางเวลาจะบังคับกฎให้เอง ไม่ต้องหวังให้ agent จำ
6. **เปลี่ยน cadence ต้องไล่หาเงื่อนไขที่ผูกกับ "วันไหน" ในพรอมป์ตด้วย** — กฎที่ผูกกับวันในสัปดาห์ตายเงียบเสมอ ไม่มี error ไม่มี log
7. **เทสต์ต้องไม่ทิ้งร่องรอยในต้นไม้ที่มันทดสอบ** — fixture ไปอยู่ temp dir
