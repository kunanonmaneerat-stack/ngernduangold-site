## 2. ⚠️ ที่ตกหล่นจริง — เจอในรอบนี้

### 2.1 post_guard รายงาน "เขียว" ทั้งที่โพสต์ล้มเหลว (บั๊กร้ายแรงที่สุดของวัน)
ledger วันนี้มีแถว:
```json
{"type":"failure","channel":"threads","clip_id":"b3-01",
 "text_first80":"NOT POSTED - Claude in Chrome extension unreachable"}
```
แต่ post_guard 20:47 รายงาน **THREADS: OK** — "Threads clip entry dated 2026-07-30 found"
เหตุ: โค้ดกรองแค่ `type=="text"` ออก **ไม่ได้กรอง `type=="failure"`** → แถวที่บันทึกว่า "ไม่ได้โพสต์" ถูกนับเป็นหลักฐานว่าโพสต์แล้ว

**guard ที่เปลี่ยนความล้มเหลวเป็นไฟเขียว อันตรายกว่าไม่มี guard เลย**
แก้: รับเฉพาะ `type` ที่ยืนยันการโพสต์จริง (`video`/`image`) · ยืนยันหลังแก้ → THREADS: UNKNOWN (ตรงความจริง)

### 2.2 post_guard บอก "YouTube token ตาย" ทั้งที่อัปสำเร็จ
รายงาน UNKNOWN + "cached YouTube token is invalid or expired" ทั้งที่เพิ่งอัปคลิปสำเร็จด้วย token ตัวเดียวกัน
เหตุ: token มีสิทธิ์ `youtube.upload` อย่างเดียว การเรียก **อ่าน** จึงได้ 403 เป็นปกติ แต่ถูกแปลว่า token เสีย
→ **ความเข้าใจผิดนี้เองที่ทำให้เลี่ยงไปอัปมือมาหลายวันทั้งที่สคริปต์ใช้ได้**
แก้: ถ้า API อ่านไม่ได้ ให้ใช้ `yt_upload_log` เป็นหลักฐาน (เขียนต่อเมื่อ YouTube คืน videoId แล้วเท่านั้น) + แก้ถ้อยคำไม่ให้ชี้ว่า credential ตาย
ยืนยันหลังแก้ → `YOUTUBE: OK — upload confirmed by yt_upload_log (fxCEKQ2Q8oE)`

### 2.3 Threads วันนี้ไม่ได้โพสต์ — Chrome extension ติดต่อไม่ได้
`list_connected_browsers` = ว่าง · task `threads-daily` รันแล้วล้มเหลว บันทึกลง ledger ถูกต้อง
**นี่คือ blocker ตัวจริงของหลายงาน** (Threads · คอมเมนต์ CTA ใต้ YT/FB · โพสต์ Pantip)

### 2.4 งานที่ยังไม่เปิดกลับ (เปิดเพิ่มแล้วรอบนี้ 3 ตัว)
เปิดเพิ่ม: `video-post-verify` (21:30) · `channel-heartbeat` (21:00) · `knowledge-post-noon` (12:30)
**ยังปิดไว้ตั้งใจ:** `yt-comment-link` + `fb-page-comment-link` — ทั้งคู่ต้องใช้ Chrome extension ซึ่งตอนนี้ต่อไม่ได้ เปิดไปก็ล้มทุกคืนเป็นสัญญาณรบกวน → เปิดพร้อมกันตอน extension กลับมา
