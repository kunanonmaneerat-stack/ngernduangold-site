## 5. 🔴 แดง — post-guard รายงานเท็จ (เรื่องที่ต้องแก้ก่อนเพื่อน)

**เกิดอะไรขึ้นวันนี้:** งาน Threads 19:00 **ล้มเหลว** — ลองแนบวิดีโอ 3 วิธีไม่สำเร็จ ไม่มีอะไรถูกโพสต์
task บันทึกอย่างซื่อสัตย์ว่า:

```json
{"type": "failure", "channel": "threads", "text_first80": "NOT POSTED - video attach failed", ...}
```

**แต่ post_guard อ่านรายการนี้แล้วตอบว่า OK** — ยืนยันด้วยการจำลอง logic (`tools/post_guard.py` บรรทัด 643–661) แบบอ่านอย่างเดียว:

```
guard would return: OK
  matched entry type = failure
  matched entry says : NOT POSTED - video attach failed
  -> FALSE POSITIVE
```

**สาเหตุ:** `check_threads()` กรองแค่ `type == "text"` (แพตช์บั๊ก 20 ก.ค.) แต่**ไม่ได้กรอง `type == "failure"`**
รายการล้มเหลวมี channel=threads + วันที่ตรง → ผ่านด่านทั้งหมด → คืนค่า OK

**ผลกระทบ:** ยามที่เราตั้งไว้จับ "วันไหนช่องเงียบ" ตาบอดกับกรณีที่สำคัญที่สุด คือ **วันที่พยายามแล้วล้มเหลว**
ยิ่ง task บันทึก failure อย่างซื่อสัตย์เท่าไหร่ guard ยิ่งเขียวเท็จมากเท่านั้น — และ status-2026-07-26.md วันนี้ก็เขียนว่า `THREADS | OK` ไปแล้ว

**วิธีแก้ (1 บรรทัด):**
```python
if str(entry.get("type", "")).casefold() in ("text", "failure"):
    continue
```
แล้วรัน guard ซ้ำสำหรับ 26 ก.ค. เพื่อให้ได้สถานะจริง
