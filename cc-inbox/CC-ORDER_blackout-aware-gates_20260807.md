## 3 · 🟢 งานเชิงระบบที่สำคัญที่สุด — ให้ gate ทุกตัวรู้จัก blackout เอง

`policy.json → blackouts[]` มีข้อมูลครบแล้ว บันทึกทั้งสองครั้งพร้อมสาเหตุและราคาที่จ่าย:
- **27–30 ก.ค. (4 วัน)** — ท่อขาดที่ `schedule.json`
- **3–5 ส.ค. (3 วัน)** — งาน Cowork ยิงเฉพาะตอนแอปเปิด · เจ้าของไม่อยู่ · ชั้น cron ยังเดินปกติทั้งสามวัน จึงไม่มีอะไรดูผิดปกติบนดิสก์

**ให้เพิ่มด่านนี้ในทุก gate:**
```
ก่อนคำนวณอะไรก็ตาม:
  1. อ่าน policy.json -> blackouts[]
  2. ถ้าหน้าต่างวัดผลทับกับ blackout ใด ๆ
     -> ห้ามออกคำตัดสิน ให้ออก "ยังตัดสินไม่ได้ (หน้าต่างสกปรก N วัน)"
     -> เสนอวันใหม่ = วันเดิม + จำนวนวันที่ทับ
  3. เขียนจำนวนวันสะอาดจริงไว้บนหัวรายงานเสมอ แม้จะสะอาดครบก็ตาม
```
ข้อ 3 สำคัญไม่แพ้ข้อ 2 — **ถ้าเขียนเฉพาะตอนสกปรก คนอ่านจะไม่รู้ว่ารายงานที่ไม่มีบรรทัดนี้แปลว่า "สะอาด" หรือ "ยังไม่ได้เช็ก"**

**ทำไมต้องเป็นด่านอัตโนมัติ ไม่ใช่ให้คนจำ:** วันนี้เราจับได้เพราะบังเอิญมีคนไปตรวจ Slack เท่านั้น
gate ตัวถัดไปจะเจอเรื่องเดียวกัน และตอนนั้นอาจไม่มีใครตรวจ
