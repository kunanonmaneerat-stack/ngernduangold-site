# 3 · 🟢 งานเชิงระบบที่สำคัญที่สุด — gate ทุกตัวต้องรู้จัก blackout เอง

`policy.json → blackouts[]` พร้อมใช้แล้ว:
- **27–30 ก.ค. (4 วัน)** — ท่อขาดที่ `schedule.json`
- **3–5 ส.ค. (3 วัน)** — งาน Cowork ยิงเฉพาะตอนแอปเปิด · เจ้าของไม่อยู่ · **ชั้น cron เดินปกติทั้งสามวัน จึงไม่มีอะไรดูผิดบนดิสก์**

**ให้ทำเป็นด่านมาตรฐานในทุก gate:**
```
ก่อนคำนวณอะไรก็ตาม:
  1. อ่าน policy.json -> blackouts[]
  2. clean_days = จำนวนวันในหน้าต่างที่ไม่ทับ blackout
  3. เขียน clean_days บนหัวรายงาน "เสมอ" แม้จะสะอาดครบก็ตาม
  4. ถ้า clean_days < ครึ่งหนึ่งของหน้าต่างที่ตั้งใจ
     -> ห้ามออกคำตัดสิน ให้ออก "ยังตัดสินไม่ได้ (สะอาด N/M วัน)"
     -> เสนอวันใหม่ = วันเดิม + จำนวนวันที่ทับ
```

**ข้อ 3 สำคัญไม่แพ้ข้อ 4** — ถ้าเขียนเฉพาะตอนสกปรก รายงานที่ไม่มีบรรทัดนี้จะ**แยกไม่ออกระหว่าง "สะอาด" กับ "ยังไม่ได้เช็ก"**
เป็นหลักเดียวกับที่ `uptime_check` และ `agent_gap_check` ใช้: **ตรวจไม่ได้ ต้องพูดว่าตรวจไม่ได้ ห้ามเงียบ**
