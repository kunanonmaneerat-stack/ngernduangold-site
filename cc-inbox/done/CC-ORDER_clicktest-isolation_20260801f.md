### ผมแก้ 4 จุด (มีเทสต์สองทิศครบทุกจุด)
1. **`\b` รอบคำอังกฤษใน `_DEADLINE`** — `until` เคยแมตช์ใน **`phase_until`** ซึ่งเป็น*ชื่อฟิลด์ที่พรอมป์ตควรชี้ไป* → พรอมป์ตที่ทำถูกกลับถูกตราว่าผิด
   **นี่คือบั๊ก substring ตัวที่ 5 ของวัน และอยู่ใน check ที่สร้างมาจับ drift**
2. **ข้าม task ที่เกษียณ** — ใช้ `_RETIRED` + `_description_of` ตัวเดียวกับที่ `check_dead_tooling` ใช้ (กติกาเดียวกัน: task ที่ปิดแล้วอ้างกฎเก่า = บันทึกประวัติ ไม่ใช่คำสั่ง)
3. **`_RETIRED` รับมาร์กเกอร์ที่มีของประดับ** — `[⛔ PAUSED ...]` เดิมไม่แมตช์เพราะ `⛔` ไม่ใช่ whitespace
4. **`_ABOUT_DRIFT` + `_CH_STATE`** ตัวใหม่:
   - บรรทัดที่**ยกข้อความเก่ามาห้าม** หรือเล่าว่า *"ของเดิม/เคยเขียน/ตารางเดิม"* = พูด**ถึง** drift ไม่ใช่**ก่อ** drift → ข้าม
   - ต้องมีคำบอก**สถานะช่อง** (พัก/ฟรีซ/เฟส/โควตา/เปิดอีกครั้ง/resume/quota…) ไม่ใช่แค่*ชื่อ*ช่อง → ตารางหมุนคลังไม่เข้าข่าย

⚠️ **เทสต์ของคุณจับบั๊กของผมได้ 1 ตัวระหว่างทาง** — `_CH_STATE` รอบแรกผมใส่แต่ฝั่ง "หยุด" ลืมฝั่ง "กลับมา" ทำให้เคส `พันทิป เปิดอีกครั้ง 14 ส.ค.` ของคุณหลุด · แก้แล้วโดยใส่ทั้งสองทิศ

## 🔴 งานจริงของรอบนี้ · แยก `ngernduangold-clicktest` ออกจากสถิติเงิน

### ทำไมเรื่องนี้สำคัญกว่าที่เห็น
`affiliate_click` **28 วัน = 9 ครั้ง** · clicktest รัน **3 ครั้ง/30 วัน** และมันกดลิงก์จริงทุกครั้งโดยเจตนา
→ **มากถึง 1 ใน 3 ของเมตริกเงินอาจเป็นคลิกของหุ่นยนต์เราเอง**

### ขั้นตอน

**ขั้น 1 · วัดของจริงก่อนแก้ (baseline)**
1. เปิด `ga4-metrics.csv` บันทึกค่า `affiliate_click` รวม ณ วันนี้ไว้ในรายงาน
2. อ่านพรอมป์ต `~\.claude\scheduled-tasks\ngernduangold-clicktest\SKILL.md` → ระบุให้ชัดว่ามันกดลิงก์ไหนบ้าง กี่ลิงก์ต่อรอบ
3. คูณ: กี่ลิงก์ × กี่รอบ/เดือน = **จำนวนคลิกปลอมที่คาดว่าอยู่ในตัวเลข** — เขียนตัวเลขนี้ลงรายงาน

**ขั้น 2 · เลือกวิธีแยก (เรียงตามที่ผมแนะนำ)**

| # | วิธี | ข้อดี | ข้อควรระวัง |
|---|---|---|---|
| **1** | ส่ง `traffic_type=internal` จาก Playwright context | ทดสอบได้จริงทุกอย่างเหมือนเดิม · GA4 กรองให้เอง | ต้องให้เจ้าของเปิด Data Filter "Internal Traffic" เป็น Active (อยู่ใน `OWNER-CHECKLIST_20260801.md` ข้อ 3 แล้ว) |
| 2 | GA4 property แยกสำหรับเทส | สะอาดที่สุด | ตั้งค่าเพิ่ม + ต้องสลับ measurement id ตอนเทส |
| 3 | บันทึกจำนวนคลิกที่ยิงลง `automation-log/` แล้วให้ `ga4_pull` หักออก | ทำได้ทันทีโดยไม่ต้องพึ่งเจ้าของ | เป็นการ "ลบทีหลัง" ไม่ใช่ "ไม่ปน" — ต้องเขียนกำกับในรายงานทุกครั้งว่าหักไปเท่าไร |

**ถ้าเลือกวิธี 1 แต่เจ้าของยังไม่ได้เปิด filter → ทำวิธี 3 ควบไปก่อน** อย่ารอ

**ขั้น 3 · พิสูจน์ด้วยตัวเลข ไม่ใช่คำพูด**
1. รัน clicktest **1 ครั้ง**
2. ดึง GA4 ใหม่ → `affiliate_click` ในรายงานหลัก **ต้องไม่เพิ่ม**
3. แต่ต้องยืนยันได้ว่า clicktest **ยังทำงาน** (มันต้องรายงานว่า sub_id ถูกต้องเหมือนเดิม)
   → **ถ้าตัวเลขไม่เพิ่มเพราะ clicktest พัง ไม่ใช่เพราะกรองสำเร็จ = ล้มเหลว** ต้องแยกสองอย่างนี้ให้ได้ในรายงาน

**ขั้น 4 · กันไม่ให้เกิดซ้ำ — `check_synthetic_traffic`**
เพิ่ม check ใหม่ใน preflight:

  ข้อความ: `"direct N sessions (X%) แต่ไม่มี engagement เลย — น่าจะเป็น automation ของเราเอง ไม่ใช่คน"`
