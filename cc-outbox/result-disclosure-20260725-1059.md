### 📌 ข้อมูลเพิ่มที่ตรวจเจอ — รายงานเดิมของผมคลาดเคลื่อนเล็กน้อย ขอแก้ให้ตรง
รายงานรอบก่อนผมเขียนว่า "หน้า standalone พี่น้อง**อีก 3 หน้า**เขียนชัด" — ตรวจละเอียดรอบนี้พบว่า **จริงๆ มี 2 หน้า** ที่ใช้ถ้อยคำ "หน้านี้ไม่มีลิงก์พันธมิตร" (car-pawn, old-car) ส่วนหน้าที่ 3 คือ `credit-card-salary-30000` **มี affiliate link จริง 1 ลิงก์** จึงใช้ disclosure แบบ positive (`* มีลิงก์พันธมิตร — เราอาจได้รับค่าตอบแทน...`) ซึ่ง**ถูกต้องตามมาตรฐานอยู่แล้ว** ไม่ใช่หน้าที่ต้องเทียบถ้อยคำกับ loan-approval-compare

แพทเทิร์นจริงของไซต์จึงเป็น: **ไม่มี affiliate → "หน้านี้ไม่มีลิงก์พันธมิตร" · มี affiliate → "* มีลิงก์พันธมิตร — เราอาจได้รับค่าตอบแทน..." วางเหนือ CTA แรก** — ผมใช้แพทเทิร์นนี้เป็นเกณฑ์ตรวจทั้งเว็บ

## งาน 2 — แก้ gate ให้ถูกถาวร ✅ (บั๊กใหญ่กว่าที่คิด: อยู่ใน 3 ที่ ไม่ใช่แค่สคริปต์ชั่วคราวของผม)

`plain find("มีลิงก์พันธมิตร")` จะ match `"ไม่มีลิงก์พันธมิตร"` (substring) — ผลคือ gate อาจ **ปล่อยหน้าที่มี affiliate link แต่ไม่มี disclosure จริงให้ผ่าน** ถ้าหน้านั้นบังเอิญมีคำปฏิเสธอยู่ก่อน CTA แก้แล้วทั้ง 3 จุดด้วย regex negative lookbehind `(?<!ไม่)`:

| ไฟล์ | บทบาท | ผลของบั๊ก |
|---|---|---|
| `tools/postdeploy_smoke.py` | **build gate จริงที่ Netlify รัน** (fail = deploy ล้ม) | FTC check ปล่อยผ่านผิด — ร้ายแรงสุด |
| `build_site.py` → `affil_disclose()` | ตัดสินว่าจะ inject กล่อง disclosure เหนือ CTA แรกไหม | ข้ามการใส่ disclosure ทั้งที่ควรใส่ |
| `.system_control/validate.py` | ตรวจ disclosure/caption ใน content manifest | affiliate=true แต่ caption ไม่มี disclosure ก็ผ่าน |

(กัน `ได้รับค่าตอบแทน` แบบเดียวกันด้วย · ใส่ comment อธิบายเหตุผลไว้ในโค้ดทั้ง 3 จุด กันแก้กลับ)

**Regression test 3 เคส — ผ่านหมด:**
| เคส | คาดหวัง | ผล |
|---|---|---|
| มี affiliate + disclosure จริง | ผ่าน | ผ่าน ✓ |
| มี affiliate + มีแค่ "ไม่มีลิงก์พันธมิตร" | **จับได้** | จับได้ ✓ |
| มี affiliate + ไม่มี disclosure เลย | **จับได้** | จับได้ ✓ |

> หมายเหตุ: ยังไม่มีหน้าไหนบนเว็บที่ตกหลุมบั๊กนี้จริง (ตรวจแล้ว 0 หน้า) — เป็นการปิดระเบิดเวลาก่อนเกิด
